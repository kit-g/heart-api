# Test helpers

## `request.dart`

Build `Request` objects to feed directly into route handlers, without booting
the full relic app.

```dart
final req = jsonRequest(
  method: Method.post,
  path: '/comments',
  body: {'target_type': 'workout', 'target_id': uuid, 'body': 'nice'},
)
  ..user = User(id: 'u1')
  ..commentService = mockCommentService
  ..connectionsService = mockConnectionsService;

expect(() => createComment(req), throwsA(isA<NoContent>()));
```

### Why this exists

Relic's `Request` constructor is private (`Request._`), exposed only through
`RequestInternal.create` (an extension `static const` alias).
Constructing one in a test directly takes a fair bit of incantation:

```dart
RequestInternal.create(
  Method.post,
  Uri.parse('http://localhost/...'),
  Object(),             // opaque token; tests just pass a fresh Object
  body: Body.fromString(jsonEncode({...}), mimeType: MimeType.json),
)
```

Things easy to get wrong if you re-derive this:

- The URL must be **absolute** — relic validates `url.isAbsolute` in the
  constructor. `Uri.parse('/foo')` throws; use `http://localhost/foo`.
- `Body.fromString(..., mimeType: MimeType.json)` is required — `req.json()`
  switches on `body.bodyType`, and the default `MimeType.plainText` makes it
  throw `UnimplementedError('Could not decode JSON request body')`.
- The 3rd positional arg is the connection token. In tests it's opaque;
  `Object()` works.

### Setting context on the request

Route handlers read user + services off the request via extensions:

- `req.user = User(id: '...')` (from `package:heart/globals/globals.dart`)
  — populates `req.userId`.
- `req.commentService = MockCommentService()` etc. (from
  `package:heart/middleware/database.dart`) — populates the per-service
  getters used by handlers.

Each service has a `MockXService` generated by `mockito`. To add a new one,
edit `test/mocks.dart` and re-run `dart run build_runner build
--delete-conflicting-outputs`.

### Throws-based control flow

Route handlers signal HTTP results by throwing typed exceptions:
`NoContent`, `BadRequest`, `Forbidden`, `NotFound` (see `lib/models/errors.dart`
and `heart_models`). Tests should `expect(() => handler(req), throwsA(isA<X>()))`
rather than awaiting a return value when the handler throws.

Caveat: `verify(...)` calls on async mocks must come after the throw is
observed. Use `await pumpEventQueue()` before `verify` when in doubt.
