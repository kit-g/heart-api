# v0.17.0: Reactions, a coach's assistant, and renaming an exercise

Previous tag: v0.16.0 (heart_models 2.51.0 → 2.57.1; heart_aws and heart_design unchanged).

## Compatibility

Every contract change since v0.16.0. Most of it is coaching, which no installed build calls yet:
up to 1.17.1, the app calls none of `/connections`, `/invitations`, `/keys`, `/threads`, `/push`,
`/devices/removals` or `/reactions`, and receives no push. So the tightenings below reach no
installed caller.

| Change | Kind |
|---|---|
| `PUT /exercises/:exerciseId` takes an optional `name`, with a create's rules (trimmed, non-empty, at most 200 characters). A name the user already has is `409 name_taken`. Installed builds don't send `name` on this route, so for them nothing changes | widening |
| `GET`, `PUT` and `DELETE /reactions/:targetType/:targetId`: one reaction per person on a workout, an exercise, a set or a photo. An unknown `kind` is `400 invalid_kind` | additive |
| `GET /accounts/summary` counts `reactions` among the collections an export holds | additive |
| `POST /devices/removals` stops a device's pushes, on sign-out or when they're turned off | additive |
| `PUT /keys/devices/:deviceId/vouch` attaches a vouch to a device that already published; `POST /keys/claims/:ownerId` takes `deviceIds`, the devices to take keys from, and a non-JSON body is a `415`; a queued item names its `senderUserId`; an arrival wakes its device | additive, no installed caller |
| `POST /keys/devices` answers `409 device_limit` for an eleventh device in use; publishing one that's already there tells nobody | tightening, no installed caller |
| Connections answer `name` and `avatar` of the other person, only to someone they asked or who accepted them; `role` and `domain` are lower case; the viewer-relative `id` is gone, and every `/connections/:connectionId` route takes the connection's id (a connection the caller isn't on is a `404`) | coaching, no installed reader |
| A blocked person sees the connection as ended: ending it again is a `204` that changes nothing, a status change is a `404` | tightening, no installed caller |
| Marking read or clearing a thread the caller can't read is a `403`, as reading it is; `GET /programs/:programId/changes` for a program that isn't the caller's is `404 program_not_found` rather than an empty list | tightening, no installed caller |
| Only the accept that connects tells the coach; a student hears when a coach sends them a program; a push names someone as their profile does | coaching pushes, no installed receiver |
| `GET /push/settings` adds `perPersonAs`, the roles for which a topic can be chosen for one person | additive, no installed reader |
| A workout read through someone else's relationship, a peer's or another coach's, comes without `loggedBy` and `loggedByName`; the owner and the coach who logged it still see both | narrowing of coaching data |
| `ConnectionShare` gains `assistant`, and the client summary says whether a client gives it | additive |
| `heart_models` 2.52.0 to 2.57.1: the models above. `Connection.toMap` writes lower-case words and no `id`, `Connection.id` and `Connection.fromId` are deprecated; `InvitationService.acceptInvitation`, `KeyService.enqueue` and `KeyService.publishDevice` answer records. Only the API implements those services | signature changes with no installed consumer |
| `heart_models` 2.56.0: `Program.copyWith` keeps a coach's fields | fix |
| `heart_models` 2.57.1: personal records for Weighted Body Weight: a `mostReps` over the sets with no added weight, weight records only from sets that carried some, no `oneRepMax`. It reaches the app with its next build, and `/me` and MCP with this release | fix |
| OAuth: a new scope, `read:coaching` | additive |
| 5 migrations: `exercises.coach_id`, reactions, the assistant's relation, `_bring_history_forward`, `profiles.created_at` | database; the columns that reach a response are in the rows above |

Oldest app served correctly: **1.12**, as before. `MIN_APP_VERSION` stays **1.13.0**, not
enforced. No phase of any breaking-change plan ships here.

## Developers

Detail on the token surface: https://heart-of.me/developers.html.

- **`/me`:** a Weighted Body Weight exercise (a push-up, a pull-up) now has a most-reps record over
  its sets with no added weight. Its weight records count only sets that carried added weight, so a
  bodyweight-only history no longer shows 0 kg records, and it has no estimated 1RM.
- **MCP:** `get_personal_records` changes the same way.
- **MCP:** someone who coaches can let their assistant read their clients, each client who shares it
  with the assistant, by connecting with the new `read:coaching` permission. The coach then gets
  `list_clients`, `get_coach_feed`, `list_client_workouts`, `get_client_workout`,
  `list_client_programs`, `get_client_program`, `get_client_program_changes`, `list_client_goals`,
  `list_my_library` and `get_my_library_program`. Everything a client wrote comes back quoted with
  their name. Messages and notes never reach it. Design: `docs/2026-11-09.coach-assistant.md`.
- **MCP:** an exercise that came with a coach's program is marked `quotedFrom` that coach, wherever
  the tools name it.
- **MCP:** the ChatGPT app is listed as Heart of Yours.
