# v0.8.0: the baseline for mobile 1.12

The first prod release under the compatibility floor (mobile 1.12, heart_models 2.11.0).
Ships main at 93b6c5f. Previous tag: v0.7.7 (heart_models 2.6.0).

Every contract change since v0.7.7:

| Change | Kind |
|---|---|
| Library: Weighted Distance and Weighted Duration categories, with carries, sleds and weighted holds | additive vocabulary; **1.10 and 1.11 lose the catalog** (they throw on the new category), accepted in heart-api#125 |
| Library and `GET /exercises`: `aliases` on exercises, the locale's search `glossary` | additive keys |
| `POST/GET /accounts/tokens`, `DELETE /accounts/tokens/:id` | additive routes |
| `/me/*` reads and `GET /me/export` (personal tokens only) | additive routes, a new published surface |
| heart_models 2.7.0 → 2.11.0: categories, search matching, tokens, domain rules, tolerant reads | additive |
| A same-id workout copy keeps ids, set state and unread exercises and sets | fix, no shape change |
| A JSON body with a health-shaped key is `400 health_data` | tightening; no 1.12 request body carries such a key (the one `heartRate` key in the app goes to the watch, not the API) |
| `GET /goals?archived=` accepts only a boolean | tightening; the app sends `true` or nothing |

Oldest app served correctly: **1.12**. Before 1.12, the catalog fails to load, and so does any
workout or template response carrying an exercise in the new categories (a Strong import with
carries can produce one). Everything else works.
The minimal app version doesn't move (`MIN_APP_VERSION` stays 1.0.0).

- Migrations: `search-vocabulary`, `api-tokens`, `api-usage-exports`, applied by the API deploy.
- The library sync needs `search-vocabulary`, and doesn't migrate itself. The API deploy runs first
  (dispatched from main), then the tag.
- The `exports/` one-day lifecycle rule is still unapplied in prod Terraform. Not needed for
  the release; until it's applied, large exports stay in the bucket.
