# v0.10.0: records over a span, MCP tools tightened after a real account, one error shape

Previous tag: v0.9.0 (heart_models 2.14.0, unchanged).

## Compatibility

Every contract change since v0.9.0:

| Change | Kind |
|---|---|
| `GET /me/records` and `GET /me/exercises/:exerciseId/history` take `?from=&to=` | additive query params (token surface) |
| `/v1` and `/v1/` answer `404 route_not_found` instead of API Gateway's `403 {"message": "Missing Authentication Token"}` | a status change on a path no app build calls |
| Errors API Gateway answers itself (throttled, timeout, any other 4xx or 5xx) carry `error`, `code` and `reason` in place of AWS's `{"message"}`; their statuses are unchanged | additive for the app, which reads only the status and `code`, and had no `code` from these before |
| MCP `get_personal_records` is paged by exercise and names units in its keys (`weight` → `weightKg`, `distance` → `distanceKm`, `duration` → `seconds`) | a change to a tool's output, read by models, not by app builds; see *Developers* |
| MCP tools refuse a `limit` out of range instead of clamping it | tightening on the MCP surface only; no app build calls it |
| OAuth is on in prod (it went live after v0.9.0's tag; see v0.9.0's notes) | additive surface, already live |

Oldest app served correctly: **1.12**, as before. The floor stays mobile **1.13** against API
v0.9.0, and nothing here changes what 1.13 sends or reads. `MIN_APP_VERSION` stays 1.0.0.

## Developers

- **Records and history over a span.** `GET /me/records?from=&to=` and
  `GET /me/exercises/{exerciseId}/history?from=&to=` keep to workouts started in that span: `from`
  inclusive, `to` exclusive, either one optional, each a date (`2026-01-01`, midnight UTC) or an ISO
  moment. Records over a span are the best of that span, and what each beat comes from the same
  span: "heaviest this year" is one call. A bad value, or a `from` not before `to`, is a `400`.
  The MCP tools `get_personal_records` and `get_exercise_history` take `from` and `to` the same way.
- **`get_personal_records` changed shape.** It comes a page of exercises at a time, by name
  (`limit` 1–50, default 20, and a `cursor`), since one account's records were 125 KB. Its
  measurements are named like every other tool's: `weightKg`, `distanceKm`, `seconds`.
- **Numbers are rounded** to three decimals across the MCP tools, so a stored `81.6466293334961`
  reads `81.647`.
- **Bad arguments are readable.** A malformed cursor, or a `limit` outside its range, is a tool
  error saying what to send, never an internal error.
- **`list_goals` names the exercise** a goal is on (`exerciseName`), beside its id.
- **One error shape.** Errors from the gateway in front of the API now look like the API's own:
  `{"error", "code", "reason"}`, with `throttled` (429), `timeout` (504), `route_not_found` (404),
  `server_error` (5xx) and `gateway_rejected` (other 4xx). Two refusals keep AWS's body: a path
  outside `/v1`, and a body over 10 MB (a plain-text 413). Branch on the status and `code`.

Docs: https://heart-of.me/developers.html, and the `/me` reference at
https://github.com/kit-g/heart-api/blob/main/api/docs/me.md.
