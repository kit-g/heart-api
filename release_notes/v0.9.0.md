# v0.9.0: the baseline for mobile 1.13, with the developer API, MCP and OAuth

The first prod release under the compatibility floor: mobile 1.13 against this API is the first
store release Heart promotes. From here on, every contract below is one installed builds read.
Previous tag: v0.8.0 (heart_models 2.11.0, now 2.14.0).

## Compatibility

Every contract change since v0.8.0:

| Change | Kind |
|---|---|
| `GET /me/workouts/changes`, `GET /me/records`, `GET /me/exercises/:exerciseId/history`, `GET /me/library?q=` | additive routes (token surface) |
| MCP server at `/mcp` and at `https://mcp.heart-of.me` | additive, a new published surface |
| OAuth 2.1 authorization server under `/oauth` (authorize, consent, token, register, revoke), its metadata at `heart-of.me/.well-known/oauth-authorization-server` | additive routes |
| `GET /accounts/connected-apps`, `DELETE /accounts/connected-apps/:grantId` | additive routes; no 1.12 or 1.13 build calls them |
| The token surfaces accept OAuth access tokens (`hrt_at_…`) as well as personal ones | widening |
| A stage-wide throttle: past 60 requests a second (burst 12) the gateway answers `429`, code `throttled`, with `Retry-After` | a new status under load; the app sees a failed request, as in any outage, and serves from its cache |
| heart_models 2.11.0 → 2.14.0: `toPersonalRecords`, `toSessionMetrics`, `ConnectedApp` | additive |
| Workouts carry `updated_at`, `changed_xid`, `deleted_xid` | database only, in no app response |

Oldest app served correctly: **1.12**, unchanged from v0.8.0: older builds lose the catalog, as
described there. The floor this release starts is **1.13**. `MIN_APP_VERSION` stays 1.0.0.

## Developers

Everything below needs a personal access token or an OAuth grant. The token screen comes with an
upcoming app update. Docs: https://heart-of.me/developers.html.

- **Change feed**: `GET /me/workouts/changes?since=<cursor>` returns workouts changed or deleted
  since a cursor, in order, so a sync reads only what's new. A cursor from before a database move
  is refused with `400 stale_cursor`; start again without `since`.
- **Personal records**: `GET /me/records`, per exercise, each with the set it happened on and what it beat.
- **Exercise history**: `GET /me/exercises/{exerciseId}/history`, one exercise's sessions newest first.
- **Library search**: `GET /me/library?q=`, the exercise library searched the way the app searches it.
- **MCP** at `https://mcp.heart-of.me`, read-only: `get_profile`, `list_workouts`, `get_workout`,
  `get_personal_records`, `get_exercise_history`, `search_exercises`, `list_custom_exercises`,
  `list_templates`, `list_template_folders`, `list_goals`.
- **OAuth 2.1** for assistants that connect without a pasted token: dynamic client registration
  (20 a day per address), PKCE, refresh-token rotation, revocation. Connected apps are listed and
  disconnected from the account.
- **Limits**: past the stage-wide rate the API answers `429` with code `throttled` and a
  `Retry-After` header, in the same error shape as every other error. Per-token limits are unchanged.

## After the release

OAuth went live in prod on 2026-10-08, after the tag, not with it. The tag shipped the code, but
three pieces were missing:

- **The site:** the consent page, the issuer metadata and the developers page had never been
  deployed. Prod's site was deployed by hand with `scripts/site.sh`, which is still manual.
- **Prod's sign-in config:** prod had no Firebase web app. It is now in Terraform (#147), and the
  consent page's config and `site_origin` followed (#148).
- **Sign in with Apple on the web:** Apple returns to Firebase's handler by POST, which CloudFront
  refused on `/__/auth/*` (#149). Google needed `https://heart-of.me/__/auth/handler` added to
  the prod web OAuth client, which only the Google Cloud console can do.

Verified that night by connecting Claude Code to `https://mcp.heart-of.me` and signing in with
Apple, then Google.
