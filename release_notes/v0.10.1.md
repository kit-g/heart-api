# v0.10.1: import units read as written, example templates in kilograms

Previous tag: v0.10.0 (heart_models 2.14.0, unchanged).

## Compatibility

Every contract change since v0.10.0:

| Change | Kind |
|---|---|
| `POST /workouts/imports` reads a declared unit by its letters: Strong's `mi.` is miles, `lbs.`, `Kilometers`, `KM.`, `metres` and `mile` read as what they say, where a spelling the server did not know fell back to the request's `unit` (heart-api#162) | widening: the server accepts more spellings; what it accepted before converts exactly as before |
| The example templates at `/static/templates` carry kilogram weights (60, 100, 160, …) where they carried plate-math pounds read as kilograms (heart-api#163) | content, not code: a CDN object uploaded by hand, live on dev and prod since 2026-10-10 |

Oldest app served correctly: **1.12**, as before. The floor stays mobile **1.13** against API
v0.9.0; nothing here changes what any build sends or reads. `MIN_APP_VERSION` stays 1.0.0.

Histories imported before this release with `mi.` distances keep their kilometre-scaled values:
a re-import skips workouts it already created (heart-api#162 scopes this out; heart-api#140 and
#42 are the paths to fixing stored data).
