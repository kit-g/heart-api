# Workout pauses

How a workout records the time it spent paused. This is written from the code as it stands at
`b36cfa7`; nothing here is a proposal unless it says so.

Backend ticket heart-api#95. App side heart-of-yours#134. Wire models: heart_models `2.6.0`.

## Model

A workout's `start` and `end` are true wall-clock instants, and nothing ever moves them to hide a
pause. Paused time is a list of closed intervals on the workout:

```jsonc
"pauses": [{"start": "2026-10-03T18:02:11.000Z", "end": "2026-10-03T18:09:40.000Z"}]
```

They are intervals rather than a paused-seconds total, so a reader can tell *when* a session
stopped as well as for how long. The app writes them to HealthKit as pause/resume events.

**Duration** is `end − start − Σ pauses`. That is `Workout.duration` in heart_models, and
`elapsed()` is `now − start − Σ closed pauses`. No server-side code computes a workout's length
(no stats, feed, record or export reads it), so heart_models is the one place this is defined.

**An open pause** (the active workout is paused right now) is the app's own state. It never
reaches the server, and `Workout.pauses` holds closed pauses only.

## Storage

`workouts.pauses JSONB NOT NULL DEFAULT '[]'`
([migration](https://github.com/kit-g/heart-api/blob/main/database/migrations/2026-10-03.workout-pauses.sql)).
`'[]'` means none. Every older row and every import has none, which is true: the app had no pause
before this, and Strong exports none. So there is no "unknown" state for a NULL to carry.

- **`_pauses_fit(pauses, started_at, completed_at)`** is the column's CHECK constraint. It
  requires:
  - an array of at most 100 pauses;
  - each pause ending after it starts and falling within `start..end` (only after `start` while
    `end` is NULL);
  - no overlap with the next pause. Touching ends are fine.

  Each instant is read with its own offset.
- **`_clip_pauses(pauses, start, end)`** cuts stored pauses to a new window:
  - a pause that crosses either end is shortened to it;
  - a pause left with no length is dropped;
  - a pause already inside is kept exactly as written.
- The deletion archive (`archive.deleted_workouts.pauses`) copies the column.

The server stores the pauses sorted by start, as UTC instants.

## API

Every workout read returns `pauses`: `GET /workouts/{id}`, the account's workout list, a
connection's workout, and the `POST`/`PUT`/`PATCH` responses.

| Request                        | `pauses` present                     | `pauses` absent                                                         |
|--------------------------------|--------------------------------------|-------------------------------------------------------------------------|
| `POST /workouts`               | stored as sent (after validation)    | none                                                                    |
| `PUT /workouts/{id}`           | replaces the stored list; `[]` clears | stored pauses kept, clipped to the body's `start`/`end`                 |
| `PATCH /workouts/{id}`         | replaces the stored list; `[]` clears | stored pauses kept, clipped to the `start`/`end` the patch leaves       |

`null` counts as `[]`. A body that leaves the key out is what an older client sends, so its
pauses survive. This is the same rule `note` follows (heart-api#84).

**Clipping instead of rejecting.** If a save moves `start` or `end` without sending `pauses`, the
stored pauses are cut to the new window rather than refused. An older build editing a workout's
times on a second device then still saves. A save that does send `pauses` gets no clipping: they
must fit, or it is a 400.

### Example

These are from a local run against the real `Database`, with exercises left out.

`POST /workouts` with the two pauses sent out of order:

```jsonc
// request (excerpt)
{"start": "2026-10-03T18:00:00Z", "end": "2026-10-03T19:00:00Z",
 "pauses": [{"start": "2026-10-03T18:40:00Z", "end": "2026-10-03T18:50:00Z"},
            {"start": "2026-10-03T18:02:11Z", "end": "2026-10-03T18:09:40Z"}]}

// response
{
  "id": "01a103b6-50f5-763a-880b-ca61f03a7edc",
  "name": "Push",
  "start": "2026-10-03T18:00:00.000Z",
  "end": "2026-10-03T19:00:00.000Z",
  "note": null,
  "pauses": [
    {"start": "2026-10-03T18:02:11.000Z", "end": "2026-10-03T18:09:40.000Z"},
    {"start": "2026-10-03T18:40:00.000Z", "end": "2026-10-03T18:50:00.000Z"}
  ],
  "images": []
}
// Workout.duration: 0:42:31
```

`PATCH /workouts/{id}` with `{"end": "2026-10-03T18:45:00Z"}` and no `pauses` key:

```jsonc
"pauses": [
  {"start": "2026-10-03T18:02:11.000Z", "end": "2026-10-03T18:09:40.000Z"},
  {"start": "2026-10-03T18:40:00.000Z", "end": "2026-10-03T18:45:00.000Z"}   // clipped
]
// Workout.duration: 0:32:31
```

### Errors

Every failure is `400` with `code: "invalid_pauses"`. The `reason` names the bad pause by its
index in the body as sent:

| Cause                                              | `reason`                                                  |
|----------------------------------------------------|-----------------------------------------------------------|
| not a list                                         | `pauses must be a list`                                   |
| more than 100                                      | `a workout has at most 100 pauses`                        |
| missing or unparseable `start`/`end`               | `pauses[0] needs ISO-8601 start and end`                  |
| `end` not after `start`                            | `pauses[0] must end after it starts`                      |
| overlaps another                                   | `pauses[0] overlaps another pause`                        |
| outside the workout's `start..end`                 | `every pause must lie within the workout's start and end` |

The request checks each pause on its own. The last row comes from the column's CHECK, because
only the column knows a `start` or `end` that a `PATCH` left as stored. That's also why it can't
name an index.

## heart_models 2.6.0

- `WorkoutPause` has `start`, `end` and `duration`. `fromJson` throws on a missing or invalid
  instant, and `toMap` writes UTC ISO strings.
- `Workout.pauses` is a mutable `List<WorkoutPause>`, empty when none. `fromJson` and `fromRow`
  read an absent key as none.
- `Workout.toMap` always writes `pauses`, an empty list included, because the server treats a
  present key as the new value.
- A copy with the same id (`copy(sameId: true)`) keeps the pauses as its own list. A repeat with a
  fresh id drops them.

The [CHANGELOG](https://github.com/kit-g/heart-api/blob/main/shared/heart_models/CHANGELOG.md)
entry carries the one requirement for the app: its local mirror must keep pauses on every write
path. Otherwise a re-save from the mirror sends `[]` and clears pauses recorded on another device.

## Gaps

- `PUT` still doesn't check that `start` comes before `end`, and an unparseable date becomes
  null. With `end` before `start`, clipping drops every stored pause, and a sent pause can't fit.
  This predates pauses.
- The 100-pause cap lives in both `Workout.maxPauses` and `_pauses_fit`. Change both together.
- `_pauses_fit` is declared `IMMUTABLE` for the CHECK but casts text to `timestamptz`, which
  Postgres treats as `STABLE`. That is safe because every stored instant carries an offset (the
  API writes UTC `Z`), but a hand-written row without an offset would be read in the session time
  zone.
