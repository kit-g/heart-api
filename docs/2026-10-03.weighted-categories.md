# Weighted Distance and Weighted Duration — load × distance / load × time exercises (heart-go backend)

Shipped in heart-api#85 (PRs #103 and #104, landing commits `19474e4`…`0079a6e`, `heart_models`
2.7.0). The app-side consumer is heart-of-yours#253. A record of what exists, written from the
code as it stands; nothing here is a proposal unless it says so.

Before this, no category paired a load with distance or time. A farmer's carry, a sled push or a
weighted plank had to be logged as `Cardio` (weight dropped), `Duration` (weight dropped) or a
weight × reps category (distance/time dropped). Two categories close that gap, mirroring the
existing `Cardio` (distance + time) / `Duration` (time) split.

## The categories

| `Category` | Wire value (`category`) | A set keeps | `canBeCompleted` | `total` (what `best` ranks by) | `chartsByExerciseCategory` |
|---|---|---|---|---|---|
| `weightedDistance` | `Weighted Distance` | `weight` (kg) + `distance` (km) | both present | weight × distance (kg·km) | `topSetWeight`, `cardioDistance` |
| `weightedDuration` | `Weighted Duration` | `weight` (kg) + `duration` (s) | both present | weight × seconds | `topSetWeight`, `totalTimeUnderTension` |

- Units are the canonical ones every set already uses: kilograms, kilometres, seconds. A carry's
  distance is usually tens of metres, so a typical value is `0.02`–`0.1`.
- `ExerciseSet`'s constructor and `setMeasurements` keep only the category's two measurements, as
  for every other category; `reps` and the third measurement are dropped.
- `canSwitchTo` is false to and from both: switching would drop a measurement.
- Warm-ups stay out of `best` and `total`, as for every category.
- Chart types are reused, not new, so `ChartPreferenceType` and the goals metric CHECK are unchanged.

## Server

No migration. `exercises.category` is free `TEXT`, and `exercise_sets` already had `weight`,
`reps`, `duration` and `distance`. The API validates a custom exercise's category only as a string
(≤ 100 chars), so the new values were accepted before any code changed.

**Strong import** (`api/lib/models/imports.dart`, `_category`). An exercise the import has to
create gets its category from the equipment modifier in its name, otherwise from what its sets
record:

| Sets record | Category before | Category now |
|---|---|---|
| weight + distance | `Cardio` | `Weighted Distance` |
| weight + seconds (no distance) | `Weighted Body Weight` | `Weighted Duration` |
| distance, no weight | `Cardio` | `Cardio` |
| seconds, no weight | `Duration` | `Duration` |

Strong writes `0` for an unset field and the import reads it as absent, so ordinary lifts (whose
`Seconds` column is `0`) don't land in `Weighted Duration`.

## Gaps

- **`Category.fromString` throws on an unknown value.** A build on `heart_models` < 2.7.0 fails to
  parse any exercise in these categories, whether it arrives from the CDN library, `GET
  /v1/exercises`, a workout or a template. There is no lenient category read like
  `SetType.lenient`.
- **A save clears measurements outside the category.** The workout save replaces all four
  measurement columns from the payload, and `ExerciseSet` only keeps its category's own. A value
  stored outside the category (an import's `reps` on a carry, say) is cleared by the first save.
- **No GIFs** for the 11 exercises yet.
- **es, fr and ru copy is unvalidated** machine translation.
- **`Cardio`'s `total` is always null**: its pattern matches `distance` as an `int`, and
  `distance` is a `double?`. Untouched here; a `Cardio` record by duration × distance wouldn't mean
  much anyway.
