# The free program library

Ready-made programs anyone can start, served from the CDN as `static/programs`
beside `static/templates` (heart-api#198, second draft heart-api#235, the
well-known shapes heart-api#255; the app side is heart-of-yours#352). This doc
covers the source, the checks, and the shape the app reads. The programs
follow `docs/2026-10-13.programs.md` and the growth rules `heart_models`
reads (`GrowthRule`, `Progression`). The research behind them is the Notion
page "Programs — research".

## Where it lives

- **`content/sample_programs.yml`**: the programs, written to be read and
  reviewed. Targets are written as `5`, `[8, 12]` or `5+`, durations in
  seconds, and `rir` as reps in reserve. There are no weights: a weight comes
  from the user's history and the program's bases.
- **`content/program_sources.yml`**: the studies and guidelines behind each
  program and each claim its copy makes. Each one has a title, who published
  it, the year, a link, and a translated one-line finding.
- **`content/program_safety.yml`**: what the app says about safety, as notes
  each program names. The notes are:
  - a start screen;
  - when to stop;
  - normal discomfort versus pain;
  - "not a treatment plan";
  - a line for ME/CFS and long COVID;
  - a line for after childbirth.
- **`content/exercise_ladders.yml`**: the variation ladders a `ladder` rule
  names.
- **Checks:** `scripts/programs_content.py`, run by `scripts/tests`. Its
  coverage:
  - every exercise, ladder, source, safety note and next program exists;
  - every target fits its exercise's columns;
  - every rule is a kind the API knows and fits its exercise;
  - a ladder's sets top out where it climbs;
  - a wave has as many sets as its session, supplemental ones included;
  - an open slot's pattern is its exercise's movement;
  - a superset has a partner;
  - phases name real sessions, and only the last one runs on;
  - every claim cites a source and is about a part its program has;
  - every line of copy has its `es`, `fr` and `ru`.

  A test session is exempt from its rules: it is what sets the bases the
  rules then grow.
- **Render:** `uv run python scripts/programs_content.py --render programs.json`.
  The file is uploaded by hand to each environment's content bucket as
  `static/programs`, and the path invalidated, the way `static/templates` is.
  A release note carries that step.

## The shape (`static/programs`)

```json
{
  "version": 2,
  "programs": [
    {
      "key": "first_steps",
      "audience": "starting_out",
      "equipment": "none",
      "name": "First steps", "i18n": {"es": "…", "fr": "…", "ru": "…"},
      "note": "…", "noteI18n": {…},
      "who":    {"en": "…", "es": "…", "fr": "…", "ru": "…"},
      "week":   {…},
      "grows":  {…},
      "misses": {…},
      "why": [{"text": {…}, "sources": ["acsm_2026", "iversen_2021"], "about": [{"on": "week"}, {"on": "rule", "exercise": "plank"}]}],
      "sources": ["acsm_2026", "iversen_2021", "kotarsky_2018", "lee_mcgill_2015"],
      "safety": ["start", "stop_if", "discomfort"],
      "next": ["full_body_three", "full_body_muscle"],
      "perWeek": 2, "minutes": 30, "weeks": 8,
      "deload": {"every": 5, "load": 0.9, "volume": 0.5},
      "phases": [{"name": {…}, "sessions": ["<session id>"], "cycles": 1}],
      "tests": {"<session id>": {"share": 0.9}},
      "rules": {"wall-push-up": {"kind": "ladder", "rungs": ["wall-push-up", "incline-push-up", …], "top": 12, "bottom": 8}},
      "sessions": [
        {
          "id": "…", "key": "a", "name": "Day A", "i18n": {…}, "note": "…", "noteI18n": {…}, "order": 0,
          "exercises": [
            {
              "id": "…", "exercise": {"key": "sit-to-stand"}, "exercise_order": 0,
              "rest": 90, "superset": 1, "pattern": "vertical_pull", "totalReps": {"min": 50, "max": 100},
              "sets": [{"id": "…", "completed": false, "target": {"reps": {"min": 8, "max": 12}, "rir": 2}}]
            }
          ]
        }
      ]
    }
  ],
  "sources": {"acsm_2026": {"title": "…", "who": "…", "year": 2026, "url": "https://…", "finding": {"en": "…", …}, "usedBy": ["first_steps", …]}},
  "safety": {"mecfs": {"text": {"en": "…", …}, "sources": ["nice_mecfs"]}}
}
```

- **A session is a template**, in the shape `static/templates` already uses:
  exercises by library `key`, and names with an `i18n` map. The new exercise
  fields (`rest`, `superset`, `pattern`, `totalReps`) and set-target keys
  (`rir`, `share`, `supplemental`) are the ones template bodies take.
- **`rules` are keyed by exercise `key`.** A ladder's `rungs` are keys too,
  and so is a target's `of`, the lift whose training max a share is of.
  When the app copies a program, it resolves every key through its library
  and posts `POST /programs` with ids. `source` is set to the program's `key`.
  `phases` and `tests` name sessions by their ids here, which the copy
  replaces with the new template ids.
- **Copy for the program page:**
  - `who` says who the program is for.
  - `week` is what a week looks like.
  - `grows` is how it grows, in one sentence.
  - `misses` is what a miss does.
  - `why` is the research behind it, each claim with its source keys and
    what it is `about` (below).
  - `next` is where to go when it ends.
  - The research links are `sources`, resolved through the top-level
    `sources` map, where `usedBy` lists the programs citing each one.
- **A claim sits where the program shows what it explains.** Its `about`
  anchors are where the app puts it, so the research appears beside the part
  it backs, not only as a list:
  - `{"on": name}` for a part of the program page: `program`, `who`,
    `week`, `grows`, `misses`, `deload`, `phases`, `tests`, `next`, or
    `rest` (its rest timers);
  - `{"on": "rule", "exercise": key}` for one exercise's rule, keyed as
    `rules` are;
  - `{"on": "session", "session": id}` for a session;
  - `{"on": "exercise", "session": id, "exercise": id}` for one exercise in
    one session, by its template exercise id.

  A claim may sit in several places and a source back several claims, so a
  plank ladder in three programs links McGill in all three. The checker
  refuses an anchor that names nothing in its program.
- **Links** go to the publisher, PubMed or PMC, or the author body's own
  page, never to a copy hosted by someone else.
- **Filters for "help me choose":** `audience`, `equipment`, `perWeek` and
  `minutes`.
- **Ids are stable across renders** (uuid5 of program, session and
  position), so a republish doesn't look like new content to a client that
  caches by id.
- **Read tolerantly**, like the exercise library: an unknown key, or a rule
  kind this build doesn't know, never fails the file.

**The well-known shapes** (heart-api#255): the last seven follow methods
people know by other names. The method is free to use, and the names and books
are their authors', so each has a descriptive name of its own, and no copy
names the original or says it is based on one. Three more wait for the engine:
a tiered program that changes the set scheme on a miss (heart-api#256), and
volume/intensity days and a ramping 5×5 (heart-api#257). Short peaking blocks
are out by choice.

**Not merged:** the three twice-a-week entries (`first_steps`, `easing_back`,
`two_days_at_home`) were going to be merged. Their `who` lines now separate
them instead: never trained, used to train, and keeping what you have at
home.

**Status:** a draft awaiting the owner's review. The programming has been
checked by no one but its author, against the research. The `es`, `fr` and
`ru` copy is machine-translated, as the exercise library's
(`docs/2026-08-29.content-localization.md`). Nothing is uploaded until both
are reviewed.

## Gaps

- **`en_CA`, `es_ES` and `fr_CA`** fall back to `en`, `es` and `fr`; their
  copy doesn't differ here.
- **Equipment is coarse.** `home` means a pair of adjustable dumbbells.
- **No balance movement group.** `single-leg-stand` sits in `mobility` until
  the library has one, so a balance hold can't be a ladder rung yet.
- **The walk runs five weeks.** A `longer` rule has no cap, so the program's
  length is what stops the walk at 30 minutes; `next` points on from there.
