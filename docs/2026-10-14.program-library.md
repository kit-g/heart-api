# The free program library

Ready-made programs anyone can start (heart-api#198), served from the CDN as
`static/programs` beside `static/templates`. This is the source, the checks,
and the shape the app reads. The programs themselves follow
`docs/2026-10-13.programs.md`.

## Where it lives

- **Source:** `content/sample_programs.yml`, written to be read and reviewed:
  targets as `5`, `[8, 12]` or `5+`, and durations in seconds. It holds no
  weights: a weight comes from the user's history and the program's bases.
- **Checks:** `scripts/programs_content.py`, run by `scripts/tests`. They cover:
  - every exercise is in the library;
  - each target fits its exercise's columns;
  - each rule is one of the five kinds, fits its exercise, and names one a
    session does;
  - `rangeThenWeight` has a range to reach the top of;
  - a `shareOfMax` wave has as many sets as its session, and those sets carry
    a share;
  - every name and note has its `es`, `fr` and `ru`.
- **Render:** `uv run python scripts/programs_content.py --render programs.json`.
  It is uploaded by hand to each environment's content bucket as
  `static/programs`, and the path invalidated, the way `static/templates` is.
  A release note carries that step.

## The shape (`static/programs`)

```json
{
  "version": 1,
  "programs": [
    {
      "key": "first_steps",
      "audience": "starting_out",
      "equipment": "none",
      "name": "First steps",
      "i18n": {"es": "…", "fr": "…", "ru": "…"},
      "note": "…",
      "noteI18n": {"es": "…", "fr": "…", "ru": "…"},
      "perWeek": 2,
      "weeks": 8,
      "rules": {"plank": {"kind": "longer", "step": 5}},
      "sessions": [
        {
          "id": "…", "key": "a", "name": "Day A", "i18n": {…},
          "note": "…", "noteI18n": {…}, "order": 0,
          "exercises": [
            {
              "id": "…", "exercise": {"key": "squat-bodyweight"}, "exercise_order": 0,
              "sets": [{"id": "…", "completed": false, "target": {"reps": {"min": 8, "max": 12}}}]
            }
          ]
        }
      ]
    }
  ]
}
```

- **A session is a template** in the shape `static/templates` already uses.
  Exercises are referenced by library `key`, and each name comes with an
  `i18n` map. The app reads both files the same way.
- **`rules` are keyed by exercise `key`**, not id. When the app copies a
  program, it resolves each key through its library, as it does a template's
  exercises, and posts `POST /programs` with ids and with `source` set to the
  program's `key`.
- **`audience`**: `starting_out`, `getting_back`, `keep_muscle` or
  `getting_stronger`. **`equipment`**: `none`, `home` or `gym`. Both are
  filters. `weeks` is left out for an ongoing program.
- **Ids are stable across renders** (uuid5 of the program, session and
  position), so a republish doesn't look like new content to a client that
  caches by id.
- Read tolerantly, like the exercise library: an unknown key or a rule kind
  this build doesn't know never fails the file.

## Gaps

- **`en_CA`, `es_ES` and `fr_CA`** fall back to `en`, `es` and `fr`. Their copy
  doesn't differ here.
- **Equipment is coarse.** `home` means a pair of dumbbells. A finer list, such
  as per-exercise equipment, can come from the exercise library when the
  filter needs it.
- **No preview of weights.** A library program can show its sets and how it
  grows, but its weights only appear once the user starts it and has bases.
