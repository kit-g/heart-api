# The exercise library on the CDN

Shipped in heart-api#65 (landing commit `5c8ead3`). A record of what exists, written from the
code as it stands; the app-side consumer is heart-of-yours#92. Nothing here is a proposal unless
it says so.

The exercise library is published as static, unauthenticated JSON on the **media distribution**,
one object per supported locale plus a manifest, so the app can load a catalog with no account
(anonymous mode, heart-of-yours#89) and so signed-in users stop reading the library through the
API. The authenticated `GET /v1/exercises` stays authoritative for the user's own exercises and
unit preferences; the CDN copy may lag it.

## Objects

```
static/exercises/index.json        manifest — which locales exist, and the publishing version
static/exercises/<locale>.json     the GET /v1/exercises body for that locale, as an anonymous caller
```

Locale names are the canonical server tags (`en`, `en_CA`, `es`, `es_ES`, `fr`, `fr_CA`, `ru`:
underscore, region upper-case) — the strings the API's own resolver returns. The set is `en` plus
the master's `locales:` list in `content/exercise_library.yml`, and it must equal
`SUPPORTED_LOCALES` in `infrastructure/app/stacks/api/lambdas.tf`.

Manifest, live from dev:

```jsonc
{
  "version": "5c8ead3a079d0c793d7dabc8f70c65306a2ded7a",   // sha of the run that published
  "generated_at": "2026-09-06T00:03:13.569376Z",
  "locales": ["en", "en_CA", "ru", "es", "es_ES", "fr", "fr_CA"]
}
```

It is byte-for-byte the API's list body for that locale with a nil user: library rows only,
`own: false`, `unit_system` / `rest_timer` null, archived rows present with `archived: true`,
ordered as the API orders (by the English master name). `Exercise.fromJson` parses it unchanged.

## How it is produced

`api/bin/publish_library.dart` builds the server's own `Database` from the `PG_*` variables the
Lambda uses and calls `getExercises(locale: …)` once per locale — the same query
(`_listExercises`) and serializer the route uses, so the shape cannot drift, and the per-field
translation fallback (`es_ES → es → en`, two translation joins and `COALESCE`) is already applied
inside each file. `scripts/publish_library.sh <bucket> <distribution-id>` runs the generator,
uploads with `aws s3 cp` under the headers below, and invalidates `/static/exercises/*` on the
media distribution.

It runs as the last step of the `sync-library` job in `.github/workflows/exercise-library.yml`,
after the Postgres sync, so the files carry the ids the sync just minted and the asset links the
assets pipeline wrote. Dev publishes on every push to `main` that touches the content, the script,
or the workflow; prod publishes on `v*` tags, like the API — that is the lag the first paragraph
allows.

## Serving

- Media distribution (`MEDIA_LINK` in the app: `dev.media.heart-of.me`, `media.heart-of.me`),
  next to `static/templates`, through a `/static/*` cache behavior with compression on
  (`infrastructure/app/stacks/cdn/main.tf`). `Accept-Encoding: gzip, br` gets `content-encoding:
  br`; the raw files are 0.7–1.2 MB each.
- `Cache-Control: public, max-age=3600` on locale files, `max-age=300` on the manifest (it is the
  freshness gate). S3 provides the ETag — CloudFront serves it weak (`W/"…"`) on compressed
  responses — and honours `If-None-Match`.
- The deploy role may invalidate the media distribution (`infrastructure/global/stack/main.tf`,
  `media_distribution_id`), so a publish lands within minutes rather than the 24 h policy default.

## Locale resolution is the client's

There is no request-time logic on the CDN, so the app picks the file: fetch the manifest, apply
the API's rule over its `locales` — exact tag, then bare language, then any supported regional
variant of that language, then `en` (`Request.locale`, `api/lib/core/request.dart`) — and fetch
that one file. The list is never hardcoded in the app; adding a locale stays a server-only change.
The API's resolver tests (`api/test/core/request_test.dart`) are the spec:

| device tag / header        | supported                          | resolves to |
|----------------------------|------------------------------------|-------------|
| `en-CA`                    | (all)                              | `en_CA`     |
| `es-MX`                    | (all)                              | `es`        |
| `en`                       | `en_CA`, `ru`                      | `en_CA`     |
| `fr-FR, de;q=0.9`          | (all)                              | `en`        |
| `ru;q=0.8, es;q=0.9`       | (all)                              | `es`        |

(A CloudFront Function and a query parameter were considered and rejected: the first is edge code,
the second cannot select an S3 object without it.)

## Gaps

- The manifest has no `heart_models` model; it is three fields and the app parses it inline. Add
  one if a second consumer appears.
- The byte-for-byte parity check against the live API needs a real token and has not been run
  against dev yet; the shape parity is pinned by the generator's unit test and the `heart_models`
  fixture test instead.
- Three stale `library/exercises_*.json` objects from May remain in the dev content bucket,
  referenced by nothing. Delete them.
- The prod media distribution id in `infrastructure/global/environments/prod/main.tf` was filled
  in by the agent from an unknown source; verify it against `aws cloudfront list-distributions`
  before the prod apply.
