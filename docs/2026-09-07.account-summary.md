# `GET /accounts/summary` — the export completeness check

Shipped. This is a record of what exists and why, not a task brief. The app side —
comparing the response against the local mirror and deciding whether to pull before
exporting — is not yet ticketed.

## The gap

The app's data export runs off its local SQLite mirror, not off the API: the export
file is written on device, from rows the device already holds. That is the right
shape (it works offline, and it is the only shape the device-only health rule
permits), but it has one hole — **the app has no way to know the mirror is whole.**
A sync that was interrupted, an account signed into on a fresh install, a replay
that stopped half way through the anonymous → account upsync
(`2026-09-05.upsync-replay.md`): in every case the local store is a *prefix* of the
account, and an export off it is silently partial. Nothing on the wire said so.

`GET /accounts/summary` is what the device compares against.

## The response

```json
{
  "collections": {
    "customExercises":     {"count": 7,   "latestId": "0197b3…"},
    "exercisePreferences": {"count": 22,  "latestId": "0198a1…"},
    "templateFolders":     {"count": 3,   "latestId": "0196ff…"},
    "templates":           {"count": 12,  "latestId": "0198c0…"},
    "templateShares":      {"count": 0},
    "workouts":            {"count": 412, "latestId": "0198d4…"},
    "workoutImages":       {"count": 38,  "latestId": "0198d4…"},
    "goals":               {"count": 3,   "latestId": "0198b2…"},
    "comments":            {"count": 5,   "latestId": "0198c9…"},
    "connections":         {"count": 2}
  }
}
```

`AccountSummary` / `CollectionSummary` / `ExportableCollection` in `heart_models`
(2.2.0). Authenticated, caller-scoped — there is no `:targetUserId` form, so a coach
cannot read a student's totals; nothing about this is a cross-user read.

### Why `latestId` and not just a count

A count answers "am I missing rows?" and nothing else. Two stores can hold the same
*number* of workouts and not the same workouts — a device that pulled 412 and a
server that has since replaced one both say 412. Ids are uuid v7, so the newest id is
also the high-water mark, and a matching count over a different head is a divergence
the count alone reads as in sync.

`connections` is the one collection without one: its rows are keyed by
`(initiator_id, target_id, domain)` and have no id of their own. The field is simply
absent there rather than null.

### What each collection means

| Key | Rows | Scope note |
|---|---|---|
| `customExercises` | `exercises` | the account's own only — a global library row is not theirs to export |
| `exercisePreferences` | `exercise_preferences` | unit, rest timer **and** chart type; they share one table |
| `templateFolders` | `template_folders` | |
| `templates` | `templates` | includes copies received from a coach — the student owns those rows |
| `templateShares` | `template_shares` | the **coach** side; a share received is already counted as the template it produced |
| `workouts` | `workouts` | |
| `workoutImages` | `workout_images` | the row, not the S3 object |
| `goals` | `goals` | definitions; health-backed progress is computed on device and never stored |
| `comments` | `comments` | authored by the account |
| `connections` | `connections` | both directions, matching `GET /connections` |

Device tokens are deliberately absent — an FCM registration is plumbing the account
happens to hold, not something a person exports. Nothing health-derived appears and
nothing can: the server stores none of it (CLAUDE.md, *The device-only health rule*),
which is what makes a complete mirror of this list a complete mirror of the account.

### Unknown keys are skipped, not fatal

`AccountSummary.fromJson` drops a collection key it does not recognize. The app pulls
`heart_models` from git `main` and can lag a server that has added one; a newer
server must not break an older app's export check. The reverse — a key the app knows
and the server omitted — reads as zero through `summary[collection]`.

## Implementation

One statement, `_accountSummary` in `api/lib/db/queries.dart`: ten CTEs cross-joined
into one row. `max(id::text)`, not `max(id)::text` — Postgres has no `max(uuid)`
aggregate, and uuids render as canonical lowercase hex with the dashes at fixed
positions, so text order is uuid order.

An unknown user id returns the same row with every count zero. There is no `NotFound`
branch: "you own nothing" is a true answer, not a missing account.

`getAccountSummary` lives on `ApiProfileService` (`api/lib/models/profile.dart`)
rather than the shared `AccountService`, for the same reason as
`ApiExercisePreferenceService` — the app implements no server-side counting, so a
method for it has no place on an interface the app also implements.

## Gaps

- **Nothing consumes it yet.** The frontend ticket for the compare-and-pull step is
  unwritten; this endpoint is the server half only.
- **Counts, not checksums.** Two stores agreeing on count and head id can still
  disagree in the middle — an edited workout, a deleted-then-recreated row. Catching
  that needs a per-collection digest, which is a much heavier query; the working
  assumption is that a truncated sync is the failure that happens and a scrambled
  middle is not.
- **No child rollups.** `workouts` counts workout rows, not their exercises, sets, or
  images-per-workout. An app that pulled 412 workout *headers* without their sets
  would look complete here. Today the app only ever writes whole workouts, so the
  header count stands in for the tree; if that stops being true this is where it
  breaks first.
- **Two of the ten collections scan.** Eight ride an existing index on their owner
  column. `comments` has no `author_id` index — every index on that table is on one
  of the four target columns — and `goals_user_id_idx` is partial on `NOT archived`,
  while an export counts archived goals too. Both are cheap at today's table sizes
  and neither is worth a migration for a call made once before an export; both are
  the first thing to fix if that changes.
- **No cache, no shortcut.** It is a full count every call — no `updated_at`
  watermark to short-circuit on. Written for "call this before you export", not for
  polling.
