# Reactions

A reaction is one person's word (`cheer`, `like`) on something they can read: a workout, an exercise
in it, a set, or a photo, the same four things a comment can be on (heart-api#369). They work like
comments, in or out of coaching: stored in clear beside the thing, and read by whoever can read it.
A reaction to a coaching message is the exception: it is an item in the thread, sealed like the
message.

## What holds

- **Who may react is who may comment.** The comments' read rule decides (`accessOfTarget`): a
  stranger is `403`, and a target the reader can't see, such as a hidden workout or, for a coach, a
  photo, is `404` like one that doesn't exist.
- **One reaction per person per thing.** Reacting again changes the word and keeps when the reaction
  was first left. Taking it off is idempotent, and needs no read: someone who can no longer read a
  workout can still take their reaction off it.
- **The vocabulary is open.** The server accepts `cheer` and `like` today and refuses any other word
  (`400 invalid_kind`). Adding one is a change to the API's list alone, with no migration and no app
  release: an app shows a word it doesn't know as a reaction all the same, and `heart_models` carries
  it as it arrived.
- **The owner hears of a new reaction** by a `reaction.created` push (visible, channel `reactions`,
  settable to `instant` or `off`), titled by what it is on: "Alex reacted to your set". A changed word
  and a reaction to one's own workout tell nobody. The push names the person as their profile does.
- **In a coaching thread,** a reaction to a message is an item of `kind: "reaction"` with
  `subjectType: "message"` and the message's id as `subjectId` (anything else is
  `400 invalid_subject`). Its content is ciphertext, with a commitment, like a message's. It doesn't
  count as unread and pushes nothing; the other person's app finds it on its next read. One reaction
  per person per message is the app's to keep: the server can't read which word it is.
- **Deleting a workout, an exercise, a set or a photo** deletes its reactions, and so does deleting
  the account that left them.

## Routes

`targetType` is `workout`, `workout_exercise`, `exercise_set` or `workout_image`; `targetId` is that
thing's id. A path that can't name one is `404`.

#### `PUT /reactions/:targetType/:targetId`

Body `{"kind": "cheer"}`. A first reaction answers **201**, a changed one **200**, both with the
reaction:

```jsonc
{
  "id": "01a1bd7a-da8c-7e1b-ad89-d47c92e465d3",
  "authorId": "FriendUid",
  "authorName": "Alex",
  "kind": "cheer",
  "targetType": "exercise_set",
  "targetId": "01a1bd7a-d9f0-7c2e-9b1a-5e2f3c4d5e6f",
  "createdAt": "2026-11-08T23:30:00.000Z"
}
```

#### `DELETE /reactions/:targetType/:targetId`

Takes the caller's reaction off. **204**, whether or not there was one.

#### `GET /reactions/:targetType/:targetId`

Who reacted, newest first (`?limit=` up to 100, default 50, and `?cursor=` from the last page), with
`counts` of every word and the caller's own as `mine` (absent when they haven't reacted). The counts
cover every reaction, not just the page.

```jsonc
{
  "reactions": [
    {
      "id": "01a1bd7a-da8c-7e1b-ad89-d47c92e465d3",
      "authorId": "FriendUid",
      "authorName": "Alex",
      "kind": "cheer",
      "targetType": "workout",
      "targetId": "01a1bd7a-d9f0-7c2e-9b1a-5e2f3c4d5e6f",
      "createdAt": "2026-11-08T23:30:00.000Z"
    }
  ],
  "counts": {"cheer": 3, "like": 1},
  "mine": "cheer",
  "cursor": "01a1bd7a-da8c-7e1b-ad89-d47c92e465d3"
}
```

Wire models: `Reaction`, `Reactions`, `ReactionTarget` in `heart_models` 2.53.0.

## Compatibility

Additive: a new table, three new routes, a new push topic, and a new thread item kind on a route no
installed build calls. Nothing an installed build reads changes.
