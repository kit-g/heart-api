# A generated OpenAPI spec: what was tried (heart-api#317)

Research, not a plan. Three experiments on the `/me` surface (21 `GET` routes), each on its
own branch, none merged. The question: can the spec come out of the code, FastAPI-style,
without a hand-kept document beside it and without making handlers uglier?

## Constraints the answer has to live with

- No runtime reflection. The binary is AOT, there are no mirrors and no macros. Whatever
  describes a type is either a value the program holds or something an analyzer reads at
  build time.
- `heart_models` is shared with the app. Its `toMap()` is the writer of most of what `/me`
  answers (a workout, its exercises and sets, an exercise), and it's tolerant: it writes back
  keys a newer build sent (`tolerant.dart`). It cannot be retyped for the server's sake.
- `/me` is published and additive-only, so writing the spec must not change a response.

## A — infer it from today's code (`research/openapi-infer`)

A tool on `package:analyzer` (`api/tool/openapi/infer.dart`, about 990 lines) reads `meRoutes`,
each handler's static return type, and each model's `toMap()` map literal: keys become
properties, `?value` and `if` make them optional, a nested `toMap()` becomes a `$ref`. It also
reads the `…Query.fromRequest` calls in handler bodies and the exceptions they throw. Nothing in
`lib/` changes.

- **Coverage:** 94% of response properties are precise (428 of 456). The 28 holes sit at 25
  sites, and the worst sit on the core payload. A workout's `exercises` and their sets are
  holes, because the tolerant `splice` of unread entries has no static type. So are raw-map
  bodies (the library programs, the goal progress), records spread from a computed map, and
  `Anomaly.observed`.
- **Inputs come out wrong, not just missing.** Validation inside a `switch` arm is invisible,
  so `/me/library`'s `q` is listed as optional although a request without it is a 400. Bounds
  passed in by the caller (`PageQuery`'s limits) and the values a `parsed()` accepts are lost.
- **Errors outside the handler are invisible:** the middleware's 401 and 429, and
  `apiHandler`'s 400 and 500.
- **It's fragile in silent ways.** It recognizes our idioms by name and shape: `Paginated`,
  `Created`, the parse helpers, `toIso8601String`. Filling `MeProfile.toMap` through a local
  map instead of a literal dropped `id` from the spec with no hole recorded. A raw
  `queryParameters['x']` read, delegation deeper than two levels, or a new wrapper type would
  disappear the same way.
- **What's worth keeping:** a conformance harness. An `AppHarness.observe` hook reruns the
  HTTP tests and validates every response against the spec. On its first run it found the
  undeclared 401 and 429.

Verdict: it can't be the published source. It's correct only while nobody writes Dart it doesn't
expect, and the holes are where the data is.

## B — declare it, and let the declaration do the work (`research/openapi-codecs`)

Three small pieces (`api/lib/core/openapi/`, about 1,000 lines with comments). Each turns a
declaration into the thing the code runs, so the spec can't say something the server doesn't
do.

- **`Shape<T>`** encodes a value *and* describes it. An API-owned model's `toMap()` becomes
  `shape.encode(this)`, and the field list reads like the map literal it replaces:

  ```dart
  static final Shape<MeProfile> shape = .object('MeProfile', {
    'id': .required(.string, (me) => me.user.id),
    'username': .optional(.string, (me) => me.user.displayName),
    'counts': .required(_counts, (me) => me.summary),
  });
  ```

  For a `heart_models` type, `Shape.model` only describes it (`api/lib/models/wire.dart`,
  133 lines for workout, exercise, set, target and the rest). `toMap()` still writes it, and
  each encode checks the one against the other while asserts are on, which is every test run.
  `additionalProperties: false` is the default, so a key nobody declared (a `heartRate`,
  say) fails the first test that returns it.
- **`Query`** is `parse.dart`'s query reader as a class, with the same method names. Run in
  recording mode, every read answers a stand-in value and notes its name, type, bounds and
  default. An input's `read` is then both the parser and the parameter list. There's no
  second declaration of a parameter anywhere.
- **`Endpoint.of(handler, input:, reply:, errors:)`** binds them. The handler receives its
  typed input (`getMyRecords(Request req, RecordsQuery query)`), and the router encodes the
  result through the reply's shape. Dart's inference ties the three types together: a
  handler returning `MeRecords` won't compile against `.json(MeWorkout.shape)`. A thrown
  `ApiException` the route didn't declare fails an assert, so the error list can't fall
  behind the code either.

The `/me` table became an `EndpointTable` with 9 routes declared and 12 left
`.undeclared(handler)`. Those are served as before and listed in the spec as undeclared, so
the migration can go one route at a time. The spec:

- is committed as `api/openapi/me.json`, held to the declarations by a golden test, so every
  contract change shows up as a reviewable diff;
- passes `openapi-spec-validator`;
- is served with Swagger UI at `/docs` when `API_DOCS=true`, so each environment chooses.

**Where it costs:**

- A route entry grows from one line to about six (summary, input, reply, errors). Handlers
  get shorter: the `…ById` wrappers and the `rawPathParameters` lookups go, because the path
  parameter arrives as an argument.
- `wire.dart` repeats `heart_models`' wire in a second place. The assert keeps it honest only
  for the branches tests reach: an optional key no fixture carries (a thumbnail, a target)
  could drift without failing anything. The fix is fixtures, or shapes living in
  `heart_models` itself as new public API.
- A recording run executes the reader's code with stand-in values. A check that runs before
  the reads finish (`q`'s non-empty check) throws during recording. The fix is the reason the
  spec improved: `q` became a declared required read, so the spec now says what the server
  enforces.
- Checks between parameters (`from` before `to`, at most a year) stay in code and prose. A
  schema can't say them anyway.
- Small Dart friction: `.enumOf<Category>(…)` needs its type argument spelled out, and
  descriptions are strings because doc comments can't be read at runtime.
- An API-owned shape with a spread base writes the base's keys first, so `MeRecords`'
  key order changed. The JSON is equal as a map, which is all the contract promises.

Everything else held. The whole suite passes (1,033 tests). The only existing test file
rewritten is `me_test.dart`, whose calls now go through the endpoint table, which makes every
one of them a conformance test as well.

## C — generate the shapes, check them at runtime (`research/openapi-generated`)

B on top, A underneath. `toMap()` goes back to being the writer everywhere: `lib/models/me.dart`
is main's again, the map literals a developer writes anyway. A generator on `package:analyzer`
(`api/tool/openapi/shapes.dart`, about 1,070 lines, half of it A's reading code) starts from
each declared route's handler, reads the `toMap()` of the model it returns, and writes every
shape to `api/lib/models/shapes.g.dart` (350 lines, 25 shapes, 139 fields), which is committed.
The shapes are B's describe-only kind, so every encode is still checked against the `toMap()`
while asserts are on. `Query` and `Endpoint` are unchanged; the route table names the
generated shapes (`.json(meWorkoutShape)`).

- **What it reads:** a key of the literal is a property, its value's static type is the shape,
  `?value` and `if` make it optional, a nested `toMap()` is a shape of its own, an enum's
  `.value` or `.name` lists its wire words. It also knows our idioms by name, as A did:
  `toIso8601String`, `x ? 1 : 0`, heart_models' tolerant `splice`, `list.indexed` taken apart
  by a pattern, keys that are an enum's words (`SetTarget`'s ranges), a local holding a map.
- **A hole never passes.** Anything it can't type fails the run and names the key, unless
  `api/lib/models/shape_overrides.dart` says it by hand. An override nothing reads any more
  fails it too. `--check` exits non-zero when the generated file is stale, and a test in
  the suite does the same.
- **Hand-written, before and after:** B's shapes were 239 lines and 133 field declarations
  (`wire.dart`'s 133 lines, `me.dart`'s 93, `warningsShape`'s 13). C's overrides are 24
  lines, 9 entries: 4 holes (a target's and an exercise's `totalReps` carry what a newer
  build wrote; a record's kinds and a warning's `observed` are computed at runtime), 2 strings
  the server formats as moments, which no type says, and 3 descriptions.
- **The spec:** every path is the same, and so is every required or optional key. Seven
  components have the generator's names (`MeProfileCounts` for `AccountCounts`,
  `MeRecordsRecord` for `MeRecord`, …). Every property that differs, the generator has more
  right, because it reads the type where a person wrote down a guess:
  - `SetTarget.ofSlot` is a string. B's hand shape said integer, and no fixture carried one,
    so the asserts never saw it. That is the drift B's write-up warned `wire.dart` would
    allow, already there.
  - `SetTarget.rir` is a number (`num?`), not an integer; an exercise's asset and thumbnail
    sizes and a set's `duration` are integers, not numbers.
  - Five enums list their values (`Movement`'s four, `Health.activity`); B said
    string.
  - A session's `metrics` names its 11 chart keys instead of being any map of numbers.
- **Descriptions come from doc comments** where a value reads a documented member, and an API
  model's own doc describes it: 37 fields and 6 models, most of which read well (`calories`, `rpe`, `rest`,
  `hasMore`). Some don't belong in a public spec: placeholders (an image's `id` is "some sort of
  identifier."), tickets and code names (`heart-api#86`, `toSessionMetrics`), the app's point
  of view ("this build"). One says more than the hand spec did: `WorkoutExercise.met` is
  "computed on device from wearable data". Doc comments in heart_models are written for the
  app. Publishing them makes them API copy, and they'd want review as such.
- **How it fails.** A's fragility case, filling `MeProfile.toMap` through a local map and
  adding `id` after: the first generator dropped `id` silently, as A did. The asserts caught
  it, since the first HTTP test that read `/me` got a 500 from the `ShapeMismatch`. A 20-line
  rule then made the generator say it itself: ``MeProfile.?: `map` gets keys after it is
  built, which only a literal shows (lib/models/me.dart:31)``. So a miss fails either the run
  or a test, as long as some test reaches the code. What neither sees is an idiom that types
  cleanly but writes something else.
- **One change to B:** an optional key may be written as null when its shape says nullable
  (`if (spoken) 'rest': rest`). B's check refused it; nothing had exercised that case.

The whole suite passes (1,036 tests), the spec passes `openapi-spec-validator`, and a run takes
about 10 seconds.

**All 21 routes, then.** With the generator in place, declaring the other 12 took the route
entries, a `read` for three inputs, and one optional-choice reader; the shapes came out on the
first run. It grew the generated file to 53 shapes and the overrides to 22 entries in 41 lines,
which is the real price of the whole surface. The new 13 are mostly maps built before a `toMap()`
sees them (`MeGoalProgress.goals`, `MeBalance.pairs`, a program's `actions` and `skips`) and keys
an author named (a program's rules, tests, bases). The first group describes as an unknown today
and would become precise if those `toMap()`s built typed values; that's a refactor, not a limit.
Three routes answer `.unknown` whole, because what they send isn't modelled here: `/exercises`,
which passes database rows through, and the two library-program routes, which pass published
content through. The 12 routes' conformance rests on what tests return: programs and library
programs through HTTP tests, templates, folders, goals and anomalies through checks on the shapes
directly, volume and balance through route tests with little data. None of it has met real data
yet, so a run against dev's is the next check worth making.

**Out of the binary, then.** Serving the spec from the API turned out to be the one part that
had no reason to be there. `dart compile exe` measured the branch at 1.0% over `main` (+57 KB
zipped), with the routes and shapes accounting for most of it: 0.1 ms to build at startup, and
nothing per request, since asserts are off in a compiled binary. So the docs router and
`API_DOCS` are gone, and `meOpenApi` moved to `tool/openapi/spec.dart`. The committed
`api/openapi/me.json` is the artifact: `scripts/pages.sh` stages it into the site, with dev's
API host swapped in, and `site/api-reference.html` renders it with Swagger UI. The shapes stay
in the binary because the route table holds them, and that's how the compiler pairs a handler
with its response. Stripping them would give up that check for under 1%.

## Recommendation

C's responses with B's inputs, not A's tool on its own:

1. **Inputs: the recording reader.** It's the closest thing to FastAPI's parameter
   declarations Dart allows, it reads the same as `parse.dart` does today, and it can't
   drift. It is also exactly the gap relic#158 (typed binding) will fill: `Endpoint.of`'s
   `input:` should give way to Relic's when that lands.
2. **Responses: shapes generated from the `toMap()`s, held by asserts.** Responses are the
   part Relic can't give us. Without reflection, a response's schema has to be a value. B
   showed the value can be held to the code by asserts; C shows nobody has to type it. The
   generator reads what B's hand shapes guessed, so it was more right in every place they
   differed, and the asserts catch what it misreads. What's left by hand is what no reading
   can know: values computed at runtime, what a newer build wrote, and maps assembled before a `toMap()` sees them (22 entries across all 21 routes). Doc comments
   become API copy, so give them a review, or keep only the API-owned models'.
3. **Keep A's conformance idea.** B's asserts already make every route test a
   conformance test. An HTTP-level sweep like A's `AppHarness.observe` would add the
   middleware's statuses.
4. **Don't build more until Relic's design is known.** If relic#348 lands typed binding and a
   schema hook, `Shape` is what we'd plug into it. Otherwise this branch is a working
   fallback that migrates one route at a time.

## For relic#348

The data point to bring: inputs are the easy half, and typed binding solves them. Responses
are the hard half in Dart. With no reflection, the schema has to be a value, and a schema that
only describes a `toMap()` drifts. What worked was a codec, one value that both encodes and
describes, bound to the handler's return type so the compiler checks the pairing. A schema
hook that accepts such a value per route, plus asserts in debug mode, gets FastAPI's guarantee.
C adds that the value needn't be typed by hand: generated from the code that writes the
response and checked against it at runtime, it covered everything on `/me` but 9 keys.
