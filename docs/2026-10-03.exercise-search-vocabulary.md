# Exercise search vocabulary

How the exercise library carries the words lifters search by, and how `heart_models` matches a
query against them. Written from the code as it stands at `fd8fc57`; nothing here is a proposal
unless it says so.

Backend ticket heart-api#102. App side heart-of-yours#135. Wire models: heart_models `2.8.0`.

## Two kinds of vocabulary

- **Aliases** belong to one exercise in one locale: other names it goes by (`ohp`, `rdl`,
  `rompecráneos`, `румынка`). Variants may share one: `rdl` is on both the barbell and the dumbbell
  Romanian deadlift, because a lifter typing it wants both.
- **The glossary** belongs to a locale and spans the whole library: a word that stands for other
  words (`db` → dumbbell, `dc` → développé couché) or names muscles (`lats`, `dorsales`, `крылья`).

Both are library content, authored in `content/` and machine-written for es, fr and ru under the
same `validated: false` as the rest of that copy.

## Content

```yaml
# content/exercise_library.yml (the fallback locale, en)
glossary:
  en:
    db:
      words: ["dumbbell"]
    lats:
      muscles: ["latissimus_dorsi"]
exercises:
  romanian-deadlift-barbell:
    i18n:
      en:
        name: "Romanian Deadlift (Barbell)"
        aliases: ["rdl"]

# content/i18n/es.yml
glossary:
  dorsales:
    muscles: ["latissimus_dorsi"]
exercises:
  skullcrusher-barbell:
    name: Press francés (barra)
    aliases: ["rompecráneos", "skull crusher", "extensión de tríceps tumbado"]
```

- A glossary `words` entry is a phrase. It matches when each of its words is in a name or slug word.
- A glossary `muscles` entry is a muscle group (`hamstrings`) or a muscle id prefix
  (`latissimus_dorsi`). It matches an exercise's **primary** muscles: secondary involvement is too
  broad for search, since every row would answer "bis". Groups count because about 40% of the
  library is tagged by group only.

### Which vocabulary a locale serves

- **Aliases** follow the same ladder as `name`: the locale's own entry, then its base language's
  (`es_ES` → `es`), then the fallback's. An entry without `aliases` falls through; `aliases: []`
  is deliberately none.
- **Glossary**: the fallback's words, then the base language's, then the locale's own, a later
  word replacing an earlier one. The fallback's words apply in every locale because the slugs they
  expand to are English: `db` finds `bench-press-dumbbell` in any language.

### Validation

`scripts/validate_library.py` checks every served locale:

- an alias is never another exercise's full name;
- a glossary word is one lower-case word, and not itself a word of that locale's names (it would
  shadow the real word);
- every glossary phrase is found in some name, and every muscle is a known group or id prefix that
  some exercise has as a primary muscle.

## Storage

[Migration](https://github.com/kit-g/heart-api/blob/main/database/migrations/2026-10-03.search-vocabulary.sql):

- `exercises.aliases TEXT[]` and `exercise_translations.aliases TEXT[]`. NULL is "none of its
  own".
- `search_glossaries (locale TEXT PRIMARY KEY, terms JSONB)`. The sync writes one row per declared
  locale, already resolved along the ladder above, and prunes undeclared ones.

All of it is reproducible from `content/` (`make db-seed`).

## API and CDN

`GET /v1/exercises` (and therefore each CDN file under `static/exercises/`, which is that body per
locale) gains:

- `aliases` on every exercise: always an array, empty for user-created exercises and for library
  rows with none;
- `glossary` at the top level, beside `exercises`: the served locale's resolved vocabulary. A
  regional locale without a row of its own gets its base language's; no row at all is `{}`.

It is still one file and one conditional fetch per locale. An older client reads only `exercises`
and never sees the rest.

## Matching (heart_models 2.8.0)

`Exercise.match(query, glossary:)` returns a `SearchMatch`, or null when the query doesn't match.
Tiers, best first (`SearchMatch` sorts in this order):

| Tier         | When                                                                              |
|--------------|-----------------------------------------------------------------------------------|
| `prefix`     | the name starts with the query (an empty query is `prefix` for everything)        |
| `words`      | every query word is inside a name or slug word, in any order                      |
| `vocabulary` | at least one query word is found only through an alias or the glossary           |
| `typo`       | at least one query word (4+ letters) is found only one edit away from a name, slug or alias word (insertion, deletion, substitution or adjacent swap) |

The worst word decides the tier. Glossary words match whole: `lat` is not `lats`. Everything is
compared case-insensitively with Latin accents and `ё` folded. `Exercise.contains` is unchanged.

Run against the real files, best tier first:

| Locale | Query              | Finds                                                      | Tier         |
|--------|--------------------|------------------------------------------------------------|--------------|
| en     | `db incline press` | Incline Bench Press (Dumbbell)                             | `vocabulary` |
| en     | `rdl`              | both Romanian deadlifts                                    | `vocabulary` |
| en     | `lats`             | 37 exercises with the lats as a primary muscle             | `vocabulary` |
| en     | `benhc press`      | the bench press variants                                   | `typo`       |
| es     | `ohp`              | Press militar (barra), (polea), (mancuernas), …            | `vocabulary` |
| es     | `rompecraneos`     | both Press francés                                         | `vocabulary` |
| fr     | `dc`               | the Développé couché variants                              | `vocabulary` |
| ru     | `румынка`          | both Румынская тяга                                        | `vocabulary` |

Ranking within a tier, recency included, is the app's (heart-of-yours#135).

## Gaps

- `scripts/validate_library.py` mirrors `searchNormalized` from heart_models in Python, accent
  table included. Change both together.
- Aliases override down the ladder rather than merge: a locale that defines its own drops the
  fallback's for that exercise, so it repeats the ones its lifters also use (es keeps `ohp`).
- Typo tolerance is per word against whole words. A typo inside a partly typed word (`bnc`) or in
  a glossary word (`lsts`) doesn't match.
- Muscle words see primary muscles only. Exercises with no muscle tagging (2 in the library) never
  answer one.
