# Skips

"Not today" (heart-of-yours#312): a day the user chose not to train, written
from the code as it stands (heart-api#202).

## Why it exists

Heart only learned from the days someone trained. A skip turns a day off into
data the app can find patterns in, such as "you skip after a pressure drop". In
a program, a skip is how the user moves past a session without doing it.

## What is stored

| Field        | Holds                                                                                   |
|--------------|-----------------------------------------------------------------------------------------|
| `at`         | when the user decided, by the device's clock                                            |
| `reason`     | an optional one-tap tag: `tired`, `sore`, `sick`, `busy`, `just_no`, or whatever the app adds |
| `weather`    | optional `temperature` (°C), `humidity` (%), `pressure` (hPa), `pressureTrend` (hPa over 24 h) |
| `templateId` | the session set aside, when one was due                                                 |
| `programId`  | the program it belongs to                                                               |

The tags belong to the app, so the server checks only their spelling
(snake_case, at most 32 characters). Weather is a closed set of fields, each
within the range a real reading falls in (`400 invalid_weather` otherwise).
Location never arrives: the app uses it to fetch the weather, and that's all.

**The health snapshot stays on the phone.** The app records sleep, HRV,
resting heart rate and steps beside a skip. None of it reaches the server:
`Request.json()` refuses a body that carries any (`400 health_data`), and the
table has nowhere to put it.

## Links, never requirements

`templateId` and `programId` follow the workout rule
(`docs/2026-10-13.programs.md`). An id the caller doesn't own, or anything that
isn't a v7 id, reads as none, so a skip always saves. Each goes null when what
it names is deleted, and `programId` outlives the session template.

## In a program

A skip counts its session as done in the open cycle and moves on. It never
moves a base: bumps come from workouts only. Repeat is how the user redoes a
week, skipped or not.

## The API surface

- `GET /skips?cursor=&limit=`: newest first, paged by id.
- `POST /skips`: idempotent on the id (the upsync replay, after workouts),
  `201` new and `200` a replay.
- `DELETE /skips/:skipId`: `204`, and deleting what isn't there is not an
  error.

At most 10,000 skips per account (`400 skip_limit`). The account summary
counts them, so an export knows it carries them.

## Gaps

- **Workouts don't carry weather yet.** `Weather` is ready for them when
  heart-of-yours#310 lands.
- **The privacy page** says nothing about skips or weather. It changes when the
  app ships "Not today", as #312 asks.
- **Developer API and MCP.** Skips are not exposed there yet. Programs bring
  them in with heart-api#217, where position needs them.
